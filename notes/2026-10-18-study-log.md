# 학습 작업일지: Geth 시작과 JSON-RPC 입구

- 기록일: 2026-10-18
- 대화 범위: 2026-10-17~18
- 학습 배경: Unity/C# 개발 경험 약 3년. 이더리움 실행 클라이언트를 이해하면서 Go를 익히는 중.
- 방식: 코드를 읽고 질문한 세션. 실제 Geth 실행이나 동기화 실습은 진행하지 않음.

## 오늘의 질문

`eth_sendRawTransaction`은 어디로 들어오는가? 그 요청을 받는 HTTP 서버는 누가, 언제 만드는가?

## 공부한 흐름

1. `rpcstack.go`에서 요청을 받는 `ServeHTTP()`와 실제 트랜잭션 처리 함수를 구분했다.
2. 지갑의 RPC 주소를 바꾸면 내 Geth로 요청을 보낼 수 있음을 정리했다.
3. Go의 리시버·포인터·구조체·인터페이스 때문에 막혀 C#과 비교했다.
4. `mux`와 `mu`의 역할을 구분하고, 뮤텍스와 고루틴을 살펴봤다.
5. 스택과 CPU opcode까지 내려갔지만 이해가 충분하지 않아 이 부분은 보류했다.
6. `ServeHTTP()`보다 앞선 생성·시작 과정을 보기로 방향을 바꿨다.
7. `node.New()`도 최초 진입점은 아니며, 실행 파일 → Go 초기화 → `main()`부터 시작함을 확인했다.
8. 노드 생성 단계의 DB 준비와, 시작 이후 실제 동기화 단계를 구분했다.

## 확인한 것과 실행 범위

- 로컬 소스에서 함수 선언과 호출부를 검색하고 읽었다.
- Go 표준 라이브러리와 클라이언트 공식 문서를 참고했다.
- `go-ethereum/AGENTS.md`에 공부 대화 방식을 추가했다.
- `go env GOROOT`를 확인하려 했으나 현재 셸에서 `go` 명령을 찾지 못했다. Go 설치 여부 전체를 확인한 것은 아니다.
- 소스를 수정하거나 빌드·테스트·노드 실행·트랜잭션 전송·체인 동기화를 수행하지 않았다.
