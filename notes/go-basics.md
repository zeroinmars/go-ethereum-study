# C# 경험으로 정리한 Go 기본 문법

## 함수와 메서드

```go
func Hello() {} // 일반 함수

func (h *httpServer) ServeHTTP(w http.ResponseWriter, r *http.Request) {}
//   리시버                    입력 파라미터
```

- `(h *httpServer)`는 리시버다. 이 메서드를 호출한 객체를 함수 내부에서 h라고 부른다.
- `(w ..., r ...)`는 입력 파라미터다.
- 반환 타입은 입력 파라미터의 마지막 괄호 뒤에 쓴다. 이 ServeHTTP에는 반환값이 없다.
- 호출은 `h.ServeHTTP(w, r)` 형태다.
- Go에서는 보통 인스턴스 메서드라고 길게 부르기보다 메서드라고 부른다.

## 구조체와 패키지

Go에는 클래스가 없다. 구조체에 데이터를 담고, 구조체 밖에 리시버 메서드를 선언한다. 메서드가 같은 패키지의 다른 파일에 있을 수도 있다.

패키지는 관련 코드를 묶는 단위이며 클래스의 다른 이름이 아니다. C#에서는 구조체가 값 타입, 클래스가 참조 타입이고 둘 다 메서드를 가질 수 있다. Solidity 구조체 안에는 메서드를 직접 선언하지 않는다.

## 선언·주소·초기화

```go
h := &httpServer{log: logger}
```

- `:=`: 함수 안에서 새 변수를 선언하면서 값을 넣는다.
- `=`: 이미 선언된 변수에 값을 대입한다.
- `httpServer{...}`: 구조체 값을 만든다.
- `&`: 그 값의 주소를 구한다.
- `*httpServer`: httpServer를 가리키는 포인터 타입이다.
- `log: logger`: 왼쪽은 필드 이름, 오른쪽은 실제 값이나 변수다. 타입명을 대입하는 것이 아니다.
- 지정하지 않은 필드는 각 타입의 제로값으로 초기화된다.

## 인터페이스

`log.Logger`에서 log는 패키지 이름, Logger는 인터페이스 이름이다.

Go는 implements 같은 연결 선언 없이, 필요한 메서드를 정확히 모두 갖추면 인터페이스를 만족한다. 일반 데이터 필드를 인터페이스의 요구사항으로 선언하는 방식은 아니다.

Geth에서는 `log.Logger`의 실제 구현체가 이미 있으므로 다음처럼 사용할 수 있다.

```go
logger := log.Root()
h := &httpServer{log: logger}
```

## map

`map[string]string`은 키와 값이 모두 string인 매핑이다.

```go
names := make(map[string]string)
names["/health"] = "상태 확인"
```
