# 고루틴과 뮤텍스

## 정리한 내용

`go`는 함수 선언이 아니라 함수·메서드 호출 앞에 붙인다.

```go
A()    // 현재 흐름에서 실행하고, 끝나면 다음 줄
go A() // 새 고루틴에서 실행하도록 하고, 현재 흐름은 다음 줄
```

같은 함수를 두 번 go로 호출해도 서로 다른 고루틴이다. 다른 함수를 호출해도 마찬가지다. 먼저 호출한 고루틴이 먼저 실행·완료된다고 보장하지 않는다.

고루틴은 실행 상태와 자기 스택을 갖는 실행 단위다. 단일 CPU 코어에서도 번갈아 실행할 수 있고, 여러 코어에서는 병렬 실행할 수도 있다.

C# async/await와 목적이 겹치지만 실행 방식이 같지는 않다. 학습 초반에는 “종료를 기다리지 않고 별도로 실행”으로 이해하되, 함수 자체가 async 함수로 바뀌는 것은 아니라는 점을 구분한다.

## 뮤텍스를 쓰는 이유

뮤텍스는 잠금장치다. 같은 데이터에 접근하는 작업들이 같은 뮤텍스를 사용해야 보호된다. 구조체 필드에 Mutex를 넣는 것만으로 모든 접근이 자동 보호되지는 않는다.

```go
h.mu.Lock()
// 보호할 서버 상태를 확인하거나 변경
h.mu.Unlock()
```

한 고루틴이 잠근 동안 다른 고루틴이 같은 h.mu.Lock을 호출하면 그 줄에서 기다린다. Unlock 이후에는 기다리던 작업이 잠금을 얻어 진행할 수 있다.

## Geth에서 본 실제 상황

`httpServer.start()`는 mu를 잠그고 서버가 이미 시작됐는지 확인한 뒤 listener를 만든다. 함수가 끝나면 defer로 잠금을 해제한다.

동일한 서버에 start가 두 곳에서 동시에 호출된 상황을 가정하면:

- 잠금이 없을 때: 둘 다 “아직 시작 안 됨”을 보고 같은 포트를 열려고 할 수 있다.
- 잠금이 있을 때: 하나가 먼저 시작을 완료하고, 다음 작업은 이미 시작된 listener를 확인해 반환한다.

이는 동시 호출을 설명하는 가정이다. 지갑 요청마다 HTTP 서버를 새로 시작한다는 의미는 아니다.

## Mutex 구조체 안의 필드와 메서드

확인한 Go 표준 라이브러리에서는:

```go
type Mutex struct {
    _  noCopy
    mu isync.Mutex
}

func (m *Mutex) Lock() {
    m.mu.Lock()
}
```

- _ noCopy: 분석 도구가 복사 사용을 검사하도록 둔 표시다. 실제 복사를 언어 차원에서 불가능하게 만드는 기능은 아니다.
- isync: internal/sync 패키지의 별칭이다.
- 내부 mu: 실제 잠금 상태와 대기를 관리하는 구현이다.
- Lock, Unlock 등의 메서드는 구조체 밖에 선언되어 있다.
